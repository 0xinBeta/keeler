# Internal security audit, 2026-11-25

Six read-only automated audit passes (a second model family from the one that wrote most of the
code), one per area, at commit
`90ebbc2`. Each finding below was then checked against the code by a second reader. This is not an
external audit and does not replace one; the circuits have not been reviewed by a third party and
the proving keys are test keys.

No pass found a way for a user, an outsider or a keeper to take or redirect another user's funds.
The findings are about availability, operator mistakes and display.

Severity here is what the finding is worth after checking, with the likelihood on a real
deployment. "Auditor" is the severity the audit pass gave it.

## Findings and what was done

A reviewer then checked each decision and the intended fix against the code, corrected four of the
fixes, moved P-1 from accepted to fixed, and found L-1, which no audit pass had reported.

## Checked and found sound by the audit passes

- Every reserve-spending instruction needs a keeper signer; `init_reserve` also the admin.
- Each verifier's public inputs are bound to the canonical PDAs, the pinned pool viewing key, the
  mints, the vault id, `now` and the first nullifier.
- Intent proceeds and change go to the maker; owner-signed withdrawals go to the recorded owner.
- The price path checks the pinned account, its owner, discriminator, verification level, feed,
  age, sign, confidence and scaling; the test price cannot compile into a mainnet build.
- Accrual, share rounding (always against the user), the 95% borrow cap, and the liquidation rules
  (payout cap, at least one debt share removed, never healthier than the threshold).
- The page's check of keeper-built transactions rejects lookup tables, durable nonces, extra
  programs, a user fee payer, unexpected note commitments and payouts the user cannot open.
- Quote signatures bind network, program, trader, mints, amounts and expiry.
- Session and request signatures, nonces, origin, the loopback HTTP key; ticket signing and matching.
- The Squads program id, account layout and vault derivation; the deployed bytes are compared with
  the build before the hand-over.

## Not covered

The compiled Xark constraints and the proof system; the shielded pool program and its SDK; the
swap example program under `.tools/`; dependency internals; live RPC and indexer behaviour. No
audit pass ran a build, a test or a transaction.
